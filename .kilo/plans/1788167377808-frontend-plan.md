# ZeroLance Frontend Implementation Plan

## Current Frontend State

**Stack**: React 18 + Vite + wagmi v2 + RainbowKit v2 + TanStack Query + React Router

**Structure** (flat):
- `apps/frontend/src/pages/` — 30+ page components (flat, no feature folders)
- `apps/frontend/src/components/Alden.tsx` — shared UI primitives
- `apps/frontend/src/context/` — AuthContext, ConfigContext
- `apps/frontend/src/lib/api.ts` — fetch wrapper
- `apps/frontend/src/lib/types.ts` — TypeScript interfaces
- `apps/frontend/src/routes.tsx` — route definitions

**Key gaps vs new backend**:
1. Route guard checks `config.addresses.waveProgram && waveIssue && waveBuildathon` — old 3-contract model. New model: single `waveVault`.
2. `ProgramDetail.tsx` calls `/v1/wave/program/:id/wave/:i` for waves — new API is `/v1/wave/wave/:waveId`.
3. `WaveProjects.tsx` POSTs to `/v1/wave/program/:id/project` — new API is `/v1/wave/program/:id/project` with `wallet` + `repoUrl` (string, not `repoHash`).
4. Types reference old fields (`WaveProgram.genesisPool`, `WaveIssue`, `BuildathonSubmission`).
5. No OSS issue pages or buildathon team pages.

---

## Goal
Reorganize frontend into 3 feature folders (task, oss, buildathon) sharing a common wave shell. Each product surface has its own pages, types, and API calls. Routes updated to match new backend.

## Risks & Mitigations

1. **Route breakage**: Changing paths from `/v1/wave/program/:id/wave/:waveId` to `/v1/wave/wave/:waveId` breaks bookmarks. Mitigation: add redirect route or keep old path as alias in backend.
2. **Type drift**: Old types (`WaveIssue`, `BuildathonSubmission`) still in `lib/types.ts`. Mitigation: mark as deprecated, remove after migration.
3. **Auth context changes**: If `useAuthenticatedApi` hook changes, all pages break. Mitigation: keep hook signature stable.
4. **Missing pages**: Some old pages (`WaveApply`, `WaveSubmit`, `WaveAward`, `WaveProjects`) map to new pages with different shapes. Mitigation: migrate content carefully, test each page.
